###  战士 (Dev)  构建面
**职责**：从代码到服务，以最快、最简的方式交付功能。对底层基础设施几乎无感，善用 Serverless 和托管服务。

应掌握的核心技术：

- **静态站点与边缘分发**
  - `S3` 静态网站托管、`CloudFront` CDN、`Route53` DNS 路由
  - 自定义域名、HTTPS 证书（ACM）、缓存策略
- **Serverless 计算与 API**
  - `Lambda` 函数编写、事件触发、版本/别名管理
  - `API Gateway` (REST/HTTP API) 创建、部署、阶段管理
  - 熟悉 `AppSync` (GraphQL) 或 `Step Functions` 更佳
- **无服务器数据**
  - `DynamoDB` 表设计、主键/索引、容量模式 (On-demand/Provisioned)
  - `S3` 作为数据湖/资产存储、预签名 URL
  - 可选：`Aurora Serverless`、`SQS`/`SNS` 消息队列
- **身份与认证**
  - `Cognito` 用户池/身份池，OAuth 2.0 / OIDC 流
  - 与 `API Gateway` 或 `CloudFront` 的授权集成
- **可观察性基础**
  - `CloudWatch Logs` 日志查询、`X-Ray` 追踪
  - 基本的 Metrics 和仪表板 (Lambda 调用次数、错误率等)
- **基础设施即代码 (轻量)**
  - `AWS SAM` 或 `CDK` 声明 Serverless 资源
  - 理解 `template.yaml` / CDK 构造
- **Dev 哲学**
  - 事件驱动架构思维、无服务器设计模式、松耦合

> 战士轨 W1 (静态站) 和 W2 (API+Lambda+DynamoDB) 覆盖了上述核心。

### 🛡 圣骑士 (SRE/Ops)  控制面
**职责**：定义、加固并守护底层物理/虚拟基础设施。对网络、计算、存储有精密的守序掌控，确保高可用、安全及合规。

应掌握的核心技术：

- **网络设计**
  - `VPC` 规划：CIDR、子网 (公有/私有)、路由表、Internet Gateway / NAT Gateway
  - 安全组 (Stateful) 与网络 ACL (Stateless) 的精确规则
  - `VPC Peering`、`PrivateLink`、`Transit Gateway` 基础
- **计算与编排**
  - `EC2` 实例类型、AMI、启动模板、UserData
  - `Auto Scaling Groups` (ASG) 扩展策略、`Launch Template` 版本
  - 负载均衡器：`ALB` (七层) 与 `NLB` (四层) 的目标组、健康检查
- **存储底层**
  - `EBS` 卷类型 (gp3/io2)、快照、加密、RAID
  - `EFS` 共享文件系统、`S3` 的存储类与生命周期 (从 IaaS 视角)
  - 实例存储 (Ephemeral) 与持久化取舍
- **高可用与灾难恢复**
  - 多 AZ / 多 Region 架构设计
  - 备份策略 (EBS Snapshots, AWS Backup)
  - 故障转移与恢复点目标 (RPO/RTO) 概念
- **深度可观察性与告警**
  - `CloudWatch` 自定义指标、日志筛选、告警动作 (SNS/自动修复)
  - `VPC Flow Logs`、`CloudTrail` 审计
  - 系统内部监控 (CloudWatch Agent, 日志旋转)
- **安全与合规**
  - `IAM` 策略最小权限设计、角色与资源标签
  - 密钥管理 (`KMS`)、`Secrets Manager` / `Parameter Store`
  - 操作系统级加固 (安全组即防火墙)、补丁管理 (`Systems Manager`)
- **基础设施即代码 (重量级)**
  - `Terraform` 或 `CloudFormation` 定义完整 VPC + EC2 + EBS 栈
  - 状态管理、漂移检测
- **Ops 哲学**
  - 不可变基础设施、配置即代码、冗余与失败设计

> 圣骑士轨 P1 (EC2+VPC+EBS 三元组) 是控制面的最小完备原语，后续可延伸至 P3 (三层 Web) 等。

### 🧬 两者交叉的领域 (双轨皆需，深度不同)
- **IAM (身份与访问管理)**：战士需读懂策略以授权 Lambda 访问 S3；圣骑士需设计角色网络与资源边界。
- **基础网络**：战士需认知 VPC 和安全组存在；圣骑士需要亲手创建子网路由。
- **Infrastructure as Code**：战士用 SAM/CDK 轻量编排；圣骑士用 Terraform 定义全栈。
- **成本管理**：战士关注按调用付费 (Lambda)；圣骑士关注预留实例、数据传输成本。

### 学习路径建议
1. **战士先**：掌握 Serverless 思维，快速交付应用，建立构建面认知。
2. **圣骑士后**：亲手建立底层秩序，理解云的真实骨骼，获得 [守序] 属性。
3. 最终融合：任何真实系统都是两者结合 (比如在 Lambda 函数中访问 RDS 需要 VPC 配置)。双轨通关后将能自由穿梭于构建面与控制面之间。
