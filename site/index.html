码技能说明
CCCorrect CourseNavigate significant changes. May recommend start over update PRD redo architecture sprint planning or correct epics and stories.
DPDocument ProjectAnalyze an existing project to produce useful documentation.
GPCGenerate Project ContextScan existing codebase to generate a lean LLM-optimized project-context.md. Essential for brownfield projects.

WDWrite DocumentDescribe in detail what you want, and the agent will follow documentation best practices. Multi-turn conversation with subprocess for research/review.
BPBrainstorm ProjectExpert guided facilitation through a single or multiple techniques.
CBCreate BriefAn expert guided experience to nail down your product idea in a brief. a gentler approach than PRFAQ when you are already sure of your concept and nothing will sway you.
DRDomain ResearchIndustry domain deep dive subject matter expertise and terminology.
MRMarket ResearchMarket analysis competitive landscape customer needs and trends.
TRTechnical ResearchTechnical feasibility architecture options and implementation approaches.
WBPRFAQ ChallengeWorking Backwards guided experience to forge and stress-test your product concept to ensure you have a great product that users will love and need through the PRFAQ gauntlet to determine feasibility and alignment with user needs. alternative to product brief.
CUCreate UXGuidance through realizing the plan for your UX, strongly recommended if a UI is a primary piece of the proposed project.
PRDCreate Edit and Review PRDFacilitated PRD workflow — create a new PRD via coached discovery, update an existing one against a change signal, or validate a finished PRD against a checklist with an HTML findings report.
CAArchitectureOffer once requirements exist (a PRD or spec; plus UX if present) and the user is ready to move from what to how. Also offer any time independently-built parts risk diverging. Produces the architecture spine: the invariants that keep features epics and stories consistent. Comes before epics and stories and scales from a quick spine to a full architecture (brownfield: ratifies the existing codebase).
CECreate Epics and Stories
IRCheck Implementation ReadinessEnsure PRD UX Architecture and Epics Stories are aligned.
CKCheckpointGuided walkthrough of a change from purpose and context into details. Use for human review of commits branches or PRs.
CRCode ReviewStory cycle: If issues back to DS if approved then next CS or ER if epic complete.
CSCreate StoryStory cycle start: Prepare first found story in the sprint plan that is next or a specific epic/story designation.
DSDev StoryStory cycle: Execute story implementation tasks and tests then CR then back to DS if fixes needed.
ERRetrospectiveOptional at epic end: Review completed work lessons learned and next epic or if major issues consider CC.
QAQA Automation TestGenerate automated API and E2E tests for implemented code. NOT for code review or story validation — use CR for that.
SPSprint PlanningKicks off implementation by producing a plan the implementation agents will follow in sequence for every story.
SSSprint StatusAnytime: Summarize sprint status and route to next workflow.

Core · Core (11)
码技能说明
ARAdversarial ReviewUse for quality assurance or before finalizing deliverables. Code Review in other modules runs this automatically, but also useful for document reviews.
BCBMad CustomizeUse when you want to change how an agent or workflow behaves — add persistent facts, swap templates, insert activation hooks, or customize menus. Scans what's customizable, picks the right scope (agent vs workflow), writes the override to _bmad/custom/, and verifies the merge. No TOML hand-authoring required.
BHBMad Help
ECHEdge Case Hunter ReviewUse alongside adversarial review for orthogonal coverage — method-driven not attitude-driven.
EPEditorial Review - ProseUse after drafting to polish written content.
ESEditorial Review - StructureUse when doc produced from multiple subprocesses or needs structural improvement.
FIForge IdeaUse to pressure-test and harden an idea — software, business, creative, research, or life — until it proves out, hardens into something buildable, or dies cheaply. Persona-driven interrogation; optional handoff to bmad-spec or bmad-quick-dev.
IDIndex DocsUse when LLM needs to understand available docs without loading everything.
PMParty ModeOrchestrate multi-agent discussions when you need multiple perspectives or want agents to collaborate.
SDShard DocumentUse when doc becomes too large (>500 lines) to manage effectively.
SPSpecUse to distill any intent input (brief, PRD, transcript, brain dump, design folder, mixed multi-source) into a succinct, no-fluff SPEC.md contract + companions that downstream work derives from. Locks the WHAT before the HOW. Works for software, game design, research, editorial, policy, business, anything intent-bearing. Validation mode also available.
